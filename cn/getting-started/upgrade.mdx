本页说明 autClaw 应用版本如何升级，以及哪些文件会在在线升级、首启拉包或 release bundle 中被覆盖。日常升级优先使用 Web 控制台或管理员 IM 命令。

## 推荐方式：系统右上角更新

1. 打开 autClaw 网页。
2. 点击右上角的 **系统升级**。
3. 选择要升级的版本。
4. 点击 **在线升级**。
5. 按页面提示重启生效。

日常升级 autClaw 不需要重新拉取 Docker 镜像，也不需要删除并重建容器。Docker 镜像只是 runtime 基座，应用升级由 autClaw 主进程完成。

## IM 渠道更新命令

在已经接入的 IM 渠道中，管理员可以发送：

```text
更新
```

也可以发送：

```text
update
```

系统会检查最新版本、下载升级包，并在准备完成后提示你确认重启。

<Note>
  `更新` / `update` 是管理员命令。普通用户发送不会触发系统升级。
</Note>

## 更新不会覆盖什么

release bundle、Docker 首启拉包和在线升级都只覆盖系统 middleware 基线文件。

不会覆盖：

- 用户自己的 `plugin/adapters/`
- 用户自己的 `plugin/replies/`
- 用户自己的普通 `plugin/scripts/`
- 数据库和运行时依赖目录

## 系统会覆盖的 middleware 文件

```text
plugin/scripts/middleware.js
plugin/scripts/middleware.py
plugin/scripts/middleware_ql.js
plugin/scripts/middleware_ql.py
plugin/scripts/middleware_dd.js
plugin/scripts/middleware_dd.py
plugin/scripts/middleware/middleware.go
```

<Note>
  默认在线更新源和首启 release bundle 拉取目标均指向 `WGwuzhi/autClaw`。
</Note>

## 升级前检查

- 不要删除 [持久化路径](/cn/getting-started/runtime-paths) 中的数据库、插件目录和运行时依赖目录。
- 如果你只想更新 Docker 基座，使用 [autClaw Docker 运维命令](/cn/operations/docker) 拉取新镜像并重新创建容器。
- 升级后如需排查问题，先用 `docker logs -f autclaw` 查看启动日志。
