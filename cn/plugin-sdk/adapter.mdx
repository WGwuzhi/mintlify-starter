适配器是 `plugin/adapters/` 下的独立进程。你负责平台协议、账号解析、登录、事件标准化和发送；autClaw 负责进程管理、配置、账号路由、事件分发、媒体准备和发送回执。

## 选择接入形态

| 形态 | 能力声明 | 入站与出站 |
|---|---|---|
| 共享路由 | `resolve_account`、`normalize_inbound`、`build_outbound`、`decode_receipt` | 平台接入 `/api/{im_type}/receive` 或 Gateway WebSocket；worker 解析入站并构造发送包，autClaw 持有发送连接。 |
| 主动上报、自执行发送 | 四项核心能力，加 `emit_inbound_events`、`execute_outbound` | worker 持有平台连接或轮询，用 control 上报事件并调用平台 API 发送。 |
| raw ingress | `open_ingress`，发送能力按需声明 | worker 验签、解密、解析 HTTP 回调并返回平台响应。 |

声明 `open_ingress` 后，该 IM 的 receive 路由交给 `adapter_open_ingress`，不再调用账号解析和入站标准化动作。

## 声明 manifest

推荐文件名为 `adapter_{im_type}_{transport}` 加语言扩展名。在文件顶部声明：

```js
//[title: adapter_demo_http]
//[version: 1.0.0]
//[author: your-name]
//[class: 适配器]
//[language: javascript]
//[description: Demo IM 适配器]
//[im_type: demo]
//[im_type_name: Demo IM]
//[protocol: im]
//[transport: http]
//[account_id_key: bot_id]
//[param: {"scope":"account","required":true,"key":"bot_id","name":"Bot ID"}]
//[param: {"scope":"account","required":true,"key":"token","type":"secret","secret":true,"name":"Token"}]
```

| 字段 | 用法 |
|---|---|
| `im_type` | 渠道稳定标识，例如 `qq`、`tg`、`demo`。 |
| `im_type_name` | 设置页展示名称。 |
| `language` | `golang` 或 `javascript`。 |
| `protocol` | 填 `im`。 |
| `transport` | 外部入站方式：`http` 或 `ws`。 |
| `adapter_route` | 可选公开路由 key，默认使用 `im_type`。 |
| `account_id_key` | 账号配置中标识平台账号的字段。 |
| `receive_token_key` | 共享入站请求携带 token 的 query key；也可用 `Authorization: Bearer`。 |
| `param` | 表单配置；账号参数使用 `scope: "account"`，入站 token 可用 `bind: "ingress_token"`。 |
| `supports_qr_login` | 填 `true` 展示扫码入口，worker 还需声明对应能力。 |
| `dependency` | Node.js 运行依赖，例如 `{"name":"ws","manager":"npm"}`。 |

Go 文件需要构建约束，详见 [Go 适配器](/cn/plugin-sdk/adapter-go)。通用头注见 [manifest 声明头](/cn/plugin-sdk/manifest)。

## 连接与握手

读取 `AUTCLAW_ADAPTER_CONNECT_URL` 连接 control WebSocket。保留完整 URL，包括 query 参数。未提供时，使用 `ws://127.0.0.1:${AUTCLAW_PORT}/api/adapters/{im_type}/connect`，端口默认 `8200`。

1. 收到 `adapter_init`，缓存 `global_config_values`、`account_configs`、`common` 和 `host_capabilities`。
2. 按 `account_configs[].account_id` 建立索引，保存每个账号的 `instance_id`；后续事件回填这个值。
3. 发出有效的 `adapter_worker_ready`，再启动平台连接或轮询。

ready 的 `aut_params`：

```json
{
  "contract": "v6",
  "resolve_account": true,
  "normalize_inbound": true,
  "build_outbound": true,
  "decode_receipt": true,
  "execute_outbound": true,
  "supports_qr_login": false,
  "emit_inbound_events": true,
  "request_outbound": false,
  "open_ingress": false,
  "inbound_events": ["message"],
  "features": ["message.proactive"],
  "outbound_actions": ["message.send"]
}
```

`contract` 必须为 `v6`。`features` 和 `outbound_actions` 必须显式为数组，无能力时传 `[]`；缺失、`null` 或类型错误会关闭连接。能力按当前连接声明，未声明的能力不可调用。协议支持与账号实际权限分别判断。

| 声明 | 对应 control 动作 |
|---|---|
| `resolve_account` | `adapter_codec_resolve_account` |
| `normalize_inbound` | `adapter_codec_normalize_inbound` |
| `build_outbound` | `adapter_codec_build_outbound` |
| `decode_receipt` | `adapter_codec_decode_receipt` |
| `execute_outbound` | `adapter_execute_outbound` |
| `emit_inbound_events` | `adapter_emit_inbound_events` |
| `request_outbound` | `adapter_request_outbound` |
| `open_ingress` | `adapter_open_ingress` |
| `supports_qr_login` | `adapter_login_qr_start`、`adapter_login_qr_wait` |

`features` 支持 `message.streaming`、`message.typing`、`message.proactive`、`message.reaction`、`group.info`、`platform.action` 和 `action.generic`。主动发送单独声明 `message.proactive`。

## control 消息信封

```json
{"aut_action":"adapter_codec_build_outbound","aut_echo":"call_1","aut_params":{}}
```

成功和失败响应：

```json
{"aut_echo":"call_1","ok":true,"aut_params":{}}
```

```json
{"aut_echo":"call_1","ok":false,"aut_error":"发送失败原因"}
```

响应原样返回 `aut_echo`，不带 `aut_action`；`aut_params` 是对象。主动调用注册 pending、设置超时并按 `aut_echo` 匹配响应。断线时立即终止该连接的 pending 和平台循环；重连后重新初始化、声明能力。

## 上报标准事件

所有入站路径都使用同一结构：

```json
{
  "kind": "message",
  "event_type": "message",
  "event_id": "evt_1",
  "dedupe_key": "message:msg_1",
  "im_type": "demo",
  "instance_id": "inst_xxx",
  "self_id": "bot_1",
  "occurred_at": 1791417600000,
  "session": {"type":"group","chat_id":"group_1","chat_name":"测试群"},
  "actor": {"id":"user_1","name":"Alice","is_self":false},
  "message": {
    "message_id": "msg_1",
    "chain": {
      "items": [
        {"type":"text","text":"hello"},
        {"type":"image","media":{"source":{"kind":"http","value":"https://example.com/a.jpg"}}}
      ],
      "options": {"text_mode":"auto"}
    }
  }
}
```

`kind`、`event_type`、`im_type`、`instance_id` 必填。`im_type` 与来源适配器一致，`instance_id` 对应已知账号绑定。`occurred_at` 为 Unix 毫秒。`session.type` 可为 `private`、`group`、`channel`；群和频道必须提供 `chat_id`，私聊消息必须提供 `actor.id`。频道向插件投影为群会话。

### 规范事件名与载荷

`event_type` 是插件订阅值，必须精确填写下表名称：

| `kind` | `event_type` | 载荷 |
|---|---|---|
| `message` | `message` | `message`：`message_id`、`chain`、可选 `history`。 |
| `notice` | `notice` | `detail` 对象。 |
| `notice` | `group.member.join`、`group.member.leave`、`group.member.ban`、`group.member.unban` | `group_member`：必填 `group_id`、`user_id`；可选 `operator_id`、`sub_type`、`invited`。 |
| `notice` | `message.recall` | `message_recall`：必填 `message_id`；可选 `group_id`、`user_id`、`operator_id`。 |
| `request` | `request` | `detail` 对象。 |
| `request` | `group.request` | `group_request`：必填 `group_id`、`user_id`；可选 `request_id`、`operator_id`、`comment`、`sub_type`。 |
| `request` | `friend.request` | `friend_request`：必填 `user_id`；可选 `request_id`、`comment`。 |
| `meta_event` | `meta` | `detail` 对象。 |
| `payment` | `payment` | `payment`：必填 `channel`、`amount`；`payer` 为用户身份，可带 `type`、`paid_at`、`transfer_id`、`remark`、`detail`。 |

群成员、群申请、好友申请和撤回事件还必须提供非空 `event_id`、`dedupe_key` 和正数 `occurred_at`。群成员与群申请事件必须使用 `group` 会话。没有平台事件 ID 时，用规范字段构造可重复生成的稳定 ID。

消息内容只写入 `message.chain.items`。历史上下文使用 `message.history.message_ids` 和 `message.history.messages`。`raw` 可保存消息原始摘要；专用通知和请求使用表中的规范载荷，插件读取投影后的字段。

### 消息段

| 类型 | 必填内容 |
|---|---|
| `text` | `text`。 |
| `image`、`voice`、`video`、`file` | `media`，结构见下一节。 |
| `at` | `target_id`。 |
| `reply` | `reply_to_id`；可选 `reply.sender_name` 和 `reply.text`，用于显示引用上下文。 |
| `at_all` | 无额外字段。 |
| `face`、`poke`、`json`、`forward`、`node`、`nodes` | `data`，非空 JSON 对象或数组。 |
| `rps`、`dice`、`shake`、`share`、`contact`、`location`、`music`、`unknown` | `data`，保留平台组件字段的 JSON 对象或数组。 |

`chain.options.text_mode` 可用 `auto`、`plain`、`markdown`。命令匹配文本只拼接 `text` 段，提及、引用和媒体不会混入命令文本。

### 入站标准化与日志

在适配器 worker 内把平台消息转换为标准消息链。autClaw 根据消息段统一生成命令文本和日志摘要；新平台使用已有标准消息段即可接入这条链路，无需增加后端平台分支。

- 把平台提及标记转换为 `at` 或 `at_all`。如果平台回调隐含“提及机器人”，由 worker 补齐 `at`，并移除正文中的对应机器人标记。
- 保留消息段顺序和文本原有空白。解析原始文本作为备用来源时，避免重复追加已存在的提及段。
- 引用消息使用 `reply_to_id`。取得引用上下文后，可补充 `reply.sender_name`、`reply.text`；查询设置超时，失败时保留仅含 ID 的引用段。
- 上报标准消息段，由宿主生成显示摘要。`raw` 用于保留平台信息，日志显示依赖 `message.chain.items`。

例如，收到“@机器人 hello”和一张图片时，上报：

```json
{
  "items": [
    {"type":"at","target_id":"bot_1"},
    {"type":"text","text":"hello"},
    {"type":"image","media":{"source":{"kind":"http","value":"https://example.com/a.jpg"}}}
  ]
}
```

命令匹配文本为 `hello`，日志内容摘要为 `[At:bot_1] hello [图片]`。引用上下文示例：

```json
{"type":"reply","reply_to_id":"msg_0","reply":{"sender_name":"Alice","text":"original"}}
```

摘要格式对齐 AstrBot 的消息概要：按顺序显示各段，段与段之间插入一个空格，摘要保留文本段原有空白。

| 消息段 | 摘要格式 |
|---|---|
| `text` | 原文本。 |
| `at`、`at_all` | `[At:目标ID]`、`[At:全体成员]`。 |
| `image`、`face` | `[图片]`、`[表情:编号]`。表情编号取 `data.id`。 |
| `reply` | 有引用文本时为 `[引用消息(Alice: original)]`，否则为 `[引用消息]`。 |
| `forward` | `[转发消息]`。 |
| 其他标准组件 | 使用 AstrBot 的枚举占位符，例如语音 `[ComponentType.Record]`、视频 `[ComponentType.Video]`、文件 `[ComponentType.File]`、JSON `[ComponentType.Json]`。 |

纯提及、引用或媒体消息也会显示内容摘要。适配器的用户消息日志隐藏自发消息和通知、心跳等非消息事件；这不影响它们按事件契约上报。外层日志字段、首尾空白处理和多行缩进沿用 autClaw 的格式。

## 媒体与宿主解析

入站和出站都使用 `MediaRef`：

```json
{
  "source": {"kind":"platform","platform":{"im_type":"demo","reference_type":"file_id","value":"file_1","attributes":{}}},
  "display_name": "report.csv",
  "hints": {"declared_name":"report.csv","declared_mime_type":"text/csv"}
}
```

`source.kind` 为 `http`、`data_uri`、`base64`、`local_path` 时，用 `source.value` 保存来源，不带 `platform`。`platform` 来源必须带 `platform.im_type`、`reference_type`、`value`，不填写 `source.value`。

`display_name` 仅供 `file` 段使用，必须是安全文件名。`hints` 是来源提示，不代表已检测的格式。宿主返回的 `storage_name` 按真实字节生成；平台上传文件名由 worker 明确选择。

`adapter_init.host_capabilities.media_resolve: true` 时，你可在当前发送的 build 或 execute 阶段调用：

```json
{
  "aut_action": "adapter_host_media_resolve",
  "aut_echo": "media_1",
  "aut_params": {
    "execution_id": "egress_xxx",
    "segment_type": "voice",
    "media": {"source":{"kind":"http","value":"https://example.com/a.mp3"}},
    "representation": "file_path",
    "target": {"format":"opus"}
  }
}
```

`representation` 可选 `reference`、`file_path`、`temporary_url`；`target.format` 可选 `original`、`opus`、`amr`、`mp4`。返回相应的 `reference`、`file_path` 或 `url`，以及检测格式、名称、大小等信息。

能主动上传文件的平台请求 `file_path`，宿主下载、解码和校验后交给同机 worker 上传。需要平台下载地址时请求 `temporary_url`。可直接使用的 URL 或平台引用可直接转换为平台参数。

必须复用当前调用的 `execution_id`。发送完成或 control 断线后，解析资源释放；未知、已完成或跨连接的执行返回 `media_execution_invalid`。worker 无需调用清理动作，不向远端发送本地文件路径。

## 构造出站与能力映射

`adapter_codec_build_outbound` 接收 `execution_id`、`request_id`、`im_type`、`account_id`、`action`、目标字段和 `payload`。私聊目标用 `session_type: "private"` 与 `user_id`，群目标用 `session_type: "group"` 与 `chat_id`。

下面列出 worker 收到的动作与 ready 声明，避免把能力名称当成平台协议方法：

| worker 动作 | 所需声明 | payload |
|---|---|---|
| `sendText`、`sendMarkdown` | `outbound_actions: message.send` | `text` 或 `markdown`。 |
| `sendImage`、`sendQRCode`、`sendVoice`、`sendVideo`、`sendFile` | `outbound_actions: message.send` | 对应媒体内容；媒体使用 `media`。 |
| `sendMessage` | `outbound_actions: message.send` | `items` 数组，使用标准消息段。 |
| `groupInviteIn`、`groupKick`、`groupBan`、`groupUnban` | `group.member.invite`、`group.member.kick`、`group.member.ban`、`group.member.unban` | 对应群操作参数。 |
| `groupWholeBan`、`groupWholeUnban` | `group.member.ban_all`、`group.member.unban_all` | 全群禁言参数。 |
| `groupNoticeSend` | `group.notice.send` | 群公告参数。 |
| `approveGroupRequest`、`rejectGroupRequest` | `group.request.approve`、`group.request.reject` | 申请处理参数。 |
| `getGroupMemberList` | `group.members.list` | 群成员查询参数。 |
| `sendTyping`、`stopTyping` | `features: message.typing` | 平台输入状态参数。 |
| `setReaction` | `features: message.reaction` | 消息 ID 与 reaction 参数。 |
| `streamStart`、`streamUpdate`、`streamFinish` | `features: message.streaming` | 流式输出参数。 |
| `getGroupInfo` | `features: group.info` | 群信息查询参数。 |
| `platformAction`、`action` | `features: platform.action`、`action.generic` | 平台或通用动作参数。 |
| `recallMessage` | 无独立能力位，实现该动作 | `message_id` 与可选 `recall_context`。 |
| `breakIn` | 无独立能力位，实现该动作 | 对应操作参数。 |

插件的 `sendQRCode` 由宿主生成二维码图片后转换为 `sendImage`；worker 按图片发送处理。

媒体 payload 示例：

```json
{"type":"file","media":{"source":{"kind":"http","value":"https://example.com/report.csv"},"display_name":"report.csv"}}
```

build 返回 `transport: "ws"`、`raw_payload`、`await_receipt`。由 worker 发送时，额外返回 `executor: "worker"`，autClaw 会调用 `adapter_execute_outbound`，参数包含 `execution_id`、`im_type`、`account_id`、`raw_payload`。

共享发送连接需要回执时，把 `request_id` 写进平台 echo 或 nonce。`adapter_codec_decode_receipt` 返回 `matched`、`request_id`、`ok`、`error`、`data`；非回执返回 `{"matched":false}`。worker 自执行返回 `ok`、`error`、`data`。信封外层 `ok` 表示调用执行结果，参数内层 `ok` 表示平台操作结果。

### 可撤回发送回执

支持撤回的发送在 `data.sent_messages` 返回每条实际发出的消息：

```json
{"ok":true,"data":{"sent_messages":[{"message_id":"msg_1","recall_context":{"chat_id":"group_1"}}]}}
```

拆分发送时返回所有成功消息；部分失败时仍保留成功项。`recall_context` 只放撤回所需的字符串路由值，不放凭据或消息内容。autClaw 原样传给 `recallMessage`。不支持撤回或没有可靠消息 ID 时省略 `sent_messages`。

## 主动上报与游标

调用 `adapter_emit_inbound_events`，参数为 `{"im_type":"demo","events":[...]}`。返回结果示例：

```json
{
  "accepted": 2,
  "queued": 1,
  "duplicate": 1,
  "rejected": 1,
  "retryable": true,
  "outcomes": [
    {"index":0,"status":"queued"},
    {"index":1,"status":"duplicate"},
    {"index":2,"status":"rejected","reason":"queue_full"}
  ]
}
```

`queued`、`waiter_consumed`、`filtered`、`duplicate` 均可推进游标；`rejected` 不可跳过。只推进到第一个拒绝项之前，重试缺口及后续事件。超时或断线表示整批未确认，重试整批并保持相同 `dedupe_key`。

结构校验失败、来源账号不符或连接 generation 过期会整批拒绝。队列满、入站媒体准备失败可产生逐事件拒绝。去重按 `im_type` 与 `instance_id` 隔离；自发消息可被过滤。不要只根据信封 `ok` 或 `accepted` 总数推进游标。

## raw ingress

`adapter_open_ingress` 接收 `instance_id`、`request_id`、`method`、`path`、`raw_query`、多值 `headers` 与 `body_base64`。每个账号的专属回调地址为 `/api/{im_type}/receive/{ingress_id}`。

worker 返回：

```json
{
  "verified": true,
  "platform_account_id": "bot_1",
  "events": [],
  "response": {"status":200,"headers":{"Content-Type":["text/plain"]},"body_base64":"b2s="},
  "response_mode": "immediate"
}
```

`verified: false` 返回 403，不接收入站事件。`response_mode` 可为 `immediate` 或 `passive`；被动回复由 worker 在平台时限内等待插件回复并编码响应。请求与响应 body 上限 1 MiB。

## 账号、扫码与私有状态

- `adapter_request_outbound`：声明 `request_outbound` 后，用 `action`、目标字段与标准 `payload` 请求统一发送链路。可带 `execution_id` 绑定当前父执行。
- `adapter_update_account_state`：ready 后上报 `account_id`、`status`、`sendable`，可带 `alias`、`message`、`last_error`、RFC3339 时间字段与字符串 `meta`。无需独立能力位。
- 扫码登录：manifest 和 ready 同时声明 `supports_qr_login`，并提供四项核心能力。`adapter_login_qr_start` 返回 `session_key`、`qr_code_url`、`message`、`issued_at`；`adapter_login_qr_wait` 接收 `session_key`、`timeout_ms`，成功返回 `connected: true`、`account_id`、`account_config`，由 autClaw 保存账号。
- `adapter_storage_get`、`adapter_storage_set`、`adapter_storage_delete`：按 `key` 读写当前适配器的私有持久化字符串值；get 返回 `found`、`value`。用于保存游标或平台状态。

## 发布前检查
