先阅读 [适配器 v6 契约](/cn/plugin-sdk/adapter)。SDK 的 `contract` 提供 wire 常量和结构体，`worker` 提供连接、握手、重连、并发处理与主动调用。

## 创建 worker

保存为 `plugin/adapters/adapter_demo_http.go`。autClaw 启动时提供内置 SDK 构建依赖，无需在 manifest 声明 SDK dependency。

下面是生命周期骨架。它尚未实现平台协议，因此能力数组为空；实现功能后再增加声明。

```go
//go:build autclaw_demo_adapter

// [title: adapter_demo_http]
// [author: your-name]
// [version: 1.0.0]
// [class: 适配器]
// [language: golang]
// [description: Demo IM 适配器]
// [im_type: demo]
// [im_type_name: Demo IM]
// [protocol: im]
// [transport: http]
// [account_id_key: bot_id]
// [param: {"scope":"account","required":true,"key":"bot_id","name":"Bot ID"}]

package main

import (
    "context"
    "fmt"
    "log"
    "os/signal"
    "syscall"

    "github.com/WGwuzhi/autClaw/sdk/adaptersdk/contract"
    sdk "github.com/WGwuzhi/autClaw/sdk/adaptersdk/worker"
)

func handle(ctx context.Context, session *sdk.Session,
    action string, params sdk.Message) (sdk.Message, error) {
    return nil, fmt.Errorf("unsupported control action: %s", action)
}

func main() {
    ctx, stop := signal.NotifyContext(context.Background(), syscall.SIGINT, syscall.SIGTERM)
    defer stop()
    runner, err := sdk.NewRunner(sdk.Config{
        IMType: "demo",
        Capabilities: contract.Capabilities{
            Features: []contract.Capability{},
            OutboundActions: []contract.Capability{},
        },
        OnInit: func(session *sdk.Session, params sdk.Message) error {
            // 缓存配置，按 account_id 建索引并保存每个账号的 instance_id。
            return nil
        },
        OnReady: func(session *sdk.Session) {
            // 在此启动平台循环，并绑定 session.Context()。
        },
        Handle: handle,
    })
    if err != nil {
        log.Fatal(err)
    }
    if err := runner.Run(ctx); err != nil && ctx.Err() == nil {
        log.Fatal(err)
    }
}
```

`Runner` 自动写入 `contract: "v6"` 并把空的能力集合序列化为 `[]`。`OnInit` 失败时不发 ready。每次重连重新读取配置，平台循环随 `Session.Context()` 取消。

## 声明并实现能力

主动上报、自执行发送的 worker 实现四项 codec 和执行动作后，使用：

```go
capabilities := contract.Capabilities{
    ResolveAccount: true,
    NormalizeInbound: true,
    BuildOutbound: true,
    DecodeReceipt: true,
    ExecuteOutbound: true,
    EmitInboundEvents: true,
    InboundEvents: []string{"message"},
    Features: []contract.Capability{contract.CapabilityMessageProactive},
    OutboundActions: []contract.Capability{contract.CapabilityMessageSend},
}
```

将它赋给 `sdk.Config.Capabilities`，在 `Handle` 中分派：

| 常量 | 处理方式 |
|---|---|
| `contract.ActionResolveAccount` | 从 `headers`、`query`、`raw_payload` 解析账号，返回 `account_id`。多账号时不要随意选择第一个账号。 |
| `contract.ActionNormalizeInbound` | 标准化 `raw_payload`，返回 `events` 数组；使用请求中的 `instance_id`。 |
| `contract.ActionBuildOutbound` | 检查 `action`、账号、目标，构造 `raw_payload`。自发送返回 `executor: "worker"`、`transport: "ws"`、`await_receipt: false`。 |
| `contract.ActionDecodeReceipt` | 返回 `matched`、`request_id`、`ok`、`data`；不是回执返回 `matched: false`。 |
| `contract.ActionExecuteOutbound` | 用 `raw_payload` 调平台 API，返回平台 `ok`、`error`、`data`。 |

出站 `action` 使用 [worker 动作表](/cn/plugin-sdk/adapter#构造出站与能力映射)中的名称，例如 `sendText`、`sendTyping`；ready 数组使用对应语义能力。handler 返回 error 会自动生成失败信封。

## 构造与上报事件

以下片段放在平台接收循环中。ID 和文本取自当前账号及平台更新，导入 `time`：

```go
event := contract.AdapterEvent{
    Kind: contract.EventKindMessage,
    EventType: string(contract.EventTypeMessage),
    EventID: messageID,
    DedupeKey: "message:" + messageID,
    IMType: "demo",
    InstanceID: instanceID,
    SelfID: accountID,
    Session: contract.SessionIdentity{Type: contract.SessionTypePrivate},
    Actor: contract.UserIdentity{ID: userID},
    Message: &contract.MessageEvent{
        MessageID: messageID,
        Chain: contract.MessageChain{
            Items: []contract.StructuredMessageItem{
                {Type: contract.SegmentText, Text: text},
            },
        },
    },
}
if err := event.Validate(); err != nil {
    return err
}
events := []contract.AdapterEvent{event}
result, err := session.EmitInbound(ctx, "demo", events, 15*time.Second)
if err != nil {
    return err // 不推进游标，保持事件 ID 和去重 key 重试
}
advance := result.AdvanceCount(len(events))
// 只保存 advance 对应的连续已接受前缀游标。
_ = advance
```

通知、申请、撤回和支付使用 `contract` 专用结构，按 [规范事件表](/cn/plugin-sdk/adapter#规范事件名与载荷)填充。

## 解析媒体与返回回执

从 `payload.media` 或混合消息 `items[].media` 读取 `contract.MediaRef`。平台需要上传文件时，在当前 build 或 execute 内调用：

```go
result, err := session.Call(ctx, contract.ActionHostMediaResolve, sdk.Message{
    "execution_id": sdk.Text(params["execution_id"]),
    "segment_type": "image",
    "media": media,
    "representation": contract.MediaRepresentationFilePath,
    "target": contract.MediaResolveTarget{Format: contract.MediaTargetOriginal},
}, 15*time.Second)
if err != nil {
    return nil, err
}
filePath := sdk.Text(result["file_path"])
storageName := sdk.Text(result["storage_name"])
```

`media` 是本次待发送的 `contract.MediaRef`。先检查初始化中的 `host_capabilities.media_resolve`；在当前执行结束前完成上传，不缓存临时路径。音视频需转换时选择 `opus`、`amr` 或 `mp4`。

支持撤回的发送返回实际成功消息：

```go
return sdk.Message{
    "ok": true,
    "data": sdk.Message{
        "sent_messages": contract.SentMessages(messageIDs,
            map[string]string{"chat_id": chatID}),
    },
}, nil
```

拆分发送或部分失败时保留成功项；处理 `recallMessage` 时读取 `payload.message_id` 和 `payload.recall_context`。

## 并发与持久化

`Handle` 并发运行，账号快照与平台状态需同步保护。SDK 默认处理并发为 8，主动 pending 上限为 128，调用超时为 15 秒，control 帧上限为 2 MiB。平台 HTTP 调用还需单独设置超时并绑定 context。

使用 `session.StorageGet`、`StorageSet`、`StorageDelete` 保存私有字符串值，键不得为空。游标只在事件确认后持久化。

```bash
go test plugin/adapters/adapter_demo_http.go plugin/adapters/adapter_demo_http_test.go
go -C sdk/adaptersdk test ./...
```

测试文件使用相同构建约束。覆盖事件校验、能力声明、回执、媒体、断线取消和部分拒绝，再在“适配器管理”配置账号并联调。
